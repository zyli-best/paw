# 云边端协同引导

启动 Console 任务时传入客户端生成的唯一 `run_id`，且任务实际进入 `EdgeCloudOrchestrator` 后，使用与普通模式相同的状态和 steer 接口。客户端不需要知道当前是 Router、Device、Edge、Verifier 还是 Cloud。`agent_id` 仍表示工作区。

字段、错误码、curl 和调用示例见 [Steer 接口与调用逻辑](steering-api.md)。旧请求不传 `run_id` 时继续运行，状态返回任务存在，但 `can_steer=false`。协同配置开启但未实际进入协同流程的执行也不启用 steer。

## 自然推理边界

引导不改变现有协同控制流，不因新消息重试或重算 Router/Verifier，也不为剩余队列额外启动一轮推理：

| 到达时机 | 行为 |
| --- | --- |
| Router 正在推理 | 使用原路由结果；后续自然推理准备时注入 |
| 工具批次执行中 | 等批次结束，下一次自然推理准备时注入 |
| Router/Verifier 的只读工具循环仍有下一次推理 | 在既有下一轮准备请求时注入，不额外创建决策调用 |
| Verifier 不通过并按原流程交给 Cloud | Cloud 接管的推理准备时注入 |
| Verifier 通过、或业务模型完成且原流程结束 | 不追加推理，剩余输入标记 `not_applied` |
| 本轮快照、脱敏或 Scroll 过程中又收到引导 | 等下一次自然边界；若流程结束则不注入 |

`can_steer=true` 只表示当前可以接收入队，不保证还有后续推理。202 表示接收成功，`injected` 表示进入上下文，不表示推理已完成；预算失败或停止也可能发生在注入后。当前没有新增引导完成的 SSE 事件或独立回执查询接口。

## 独立控制器与幂等

协同使用 `EdgeCloudSteeringController`，不使用普通模式的 `SteeringState`、`_normal_steering` 或普通模式的取消上传辅助函数。公共 TaskTracker 只提供可选控制器注册、接口分发和生命周期通知。

同一任务内，相同 `message_id` 和相同文本返回原记录，不重复插入；同 ID 不同文本返回 409。不同 ID 按接收顺序处理。单任务最多 128 条引导，单条文本最多 16000 字符。所有网络重试必须复用首次保存的 `agent_id/chat_id/run_id/message_id/text`。

控制器覆盖整次协同任务，阶段切换时不销毁。完成、失败或停止时关闭接收，将尚未注入的条目标记为 `not_applied`，再随原 TaskTracker 清理。没有结束后的十分钟缓存或跨重启幂等。

## 上下文、Scroll 和投影

执行阶段在上下文压缩前准备引导，决策循环在既有输入整理前准备引导。原始任务先进入正式上下文，引导使用稳定 ID 的原生 user 消息；后续执行按 ID 避免再次追加原始输入。

原始任务与所有已注入引导受保护。Router 的独立 Scroll 视图保护初始路由请求；Verifier 不把引导作为证据归档或折叠；Device/Edge 输入投影显式保留本次协同引导及当前回复的 assistant 分段。压缩和最终投影后检查消息内容，防止静默丢失。受保护内容超过预算时按原错误策略处理，不在 token 计数后追加文本。

引导会在后续输入视图中持续可见，但正式会话和单个请求里按消息 ID 去重。若启用额外历史精简，协同恢复过程按消息身份保留本轮新增内容，不依赖压缩前的数组长度。未绑定协同策略时使用原路径。

## 会话、上传和脱敏

已注入引导进入正式 session 上下文，并作为 user 消息进入可选的过程保存视图及协同上传记录器。未注入条目不会在收尾时补入上下文，也不会伪装成模型见过的用户对话。

正常结束使用现有会话保存流程。停止或异常时，先收尾协同记录器，再通过原会话存储保存独立快照，并复用现有异步上传器；上传调度失败不阻断文件保存。已调度不代表远端成功接收，现有上传器没有新增持久化补传机制。

上传继续采用 `edge_cloud_trace.v2` 和唯一 `flow_id`。已注入引导正文只出现在 delta 的 user 消息中，其 metadata 带 `agent_id/chat_id/run_id/response_id/flow_id/message_id`、序号和时间。`edge_cloud.steering` 仅包含消息标识、顺序和最终状态，包括 `not_applied`；不包含排队原文。各阶段模型配置记录的 `steering_sequence` 表示该阶段最后一份捕获输入中实际携带的最大引导序号，不参与重算判断。

注入复用 `EdgeCloudRedaction` 及启动请求的脱敏配置，跨阶段共享确认结果。session 保存处理后的上下文；未开启模型输入脱敏或允许原文时，本地仍可能保留原文。Langfuse 上传副本另外执行现有脱敏。队列中的原文只在当前任务内存中保留，不属于持久化队列。

## 输出关联

协同输出与普通模式共用可选的 `message.metadata.steer_message_id`，表示该输出所依据的模型请求中最后一条引导的 `message_id`。同轮多条输入继续全部注入，输出只标记最后一条。工具结果跟随原调用；Router/Verifier 结论跟随产生该决策的推理，阶段开始提示不加标签。推理期间新收到的引导不会重标旧输出，也不会因此增加推理次数。标签改变时输出拆分消息，原生/展示会话及 Langfuse delta 保留字段。完整协议与前端处理示例见 [接口文档](steering-api.md#11-从输出判断引导已进入推理)。
